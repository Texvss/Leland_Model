================================================================================
WHY H2 FAILED: ML-SPECIFIC ANALYSIS
================================================================================

1. ML OPTIMIZATION SETUP
------------------------

Algorithm: Bayesian Optimization with Gaussian Process

Components:
  - Surrogate model: Gaussian Process (GP)
  - Acquisition function: Expected Improvement (EI)
  - Search space: A ∈ [0, 2]
  - Initial exploration: 6 random points
  - BO iterations: 12-30 iterations
  - Evaluations per point: 500-5,000 MC simulations

How it works:
  1. Random exploration finds initial landscape
  2. GP models objective function (std vs A)
  3. EI acquisition suggests next A to try
  4. Iteratively refine search toward optimum
  5. Return A with lowest measured std

2. ML ADVANTAGES OVER GRID SEARCH
----------------------------------

Why ML should be better:
  ✓ Adaptive search (focuses on promising regions)
  ✓ Fewer evaluations needed (12-30 vs 11-31 grid points)
  ✓ Models uncertainty (GP variance)
  ✓ Exploration-exploitation tradeoff (EI)
  ✓ Can find optima between grid points

Evidence ML is better than Grid:
  - Wins in 72% of cases vs Grid Search
  - TSLA ABM: ML=-$114.03 vs Grid=-$114.66 (+$0.63)
  - AAPL ABM: ML=-$14.15 vs Grid=-$14.19 (+$0.04)
  - More sample-efficient (fewer MC evaluations)

Conclusion: ML IS better optimization method than Grid Search

3. BUT ML STILL WORSE THAN CLASSICAL
-------------------------------------

Key finding: Better optimization ≠ Better result

ML finds "better" A on calibration data, but:
  - Still overfits to finite sample
  - Still doesn't beat theoretical optimum
  - Improvements are marginal and don't generalize

Example (TSLA, k=0.005):
  Classical A = 0.2153
  Grid A      = 0.1546
  ML A        = 0.2828 (31% HIGHER than Classical!)

  On calibration (500 MC paths):
    ML std = 1.2758 (best among all tested)

  On test (10,000 MC paths):
    Classical std = 1.3411 ← BEST
    ML std = 1.3669 (+1.9% worse)

ML explored different region of A space, found different local
minimum on noisy objective, but still didn't beat Classical.

4. THE FUNDAMENTAL PROBLEM
---------------------------

Issue: ML optimizes SAMPLE objective, not POPULATION objective

Monte Carlo gives us: std_sample(A) = f(A) + noise

Noise depends on:
  - Sample size (N MC paths)
  - Random seed
  - Market regime in sample

ML algorithm assumes: measured std = true std

But reality: measured std ≠ true std (sampling error)

Classical formula solves TRUE population problem analytically:
  A* = argmin E[std²(A)] + E[TC(A)]

Where E is over ALL possible paths, not just sample.

ML/Grid solve SAMPLE problem empirically:
  A* = argmin std²_sample(A) + TC_sample(A)

These are different problems! Sample optimum ≠ Population optimum

5. WHY DOESN'T MORE DATA HELP?
-------------------------------

Calibration used:
  - Grid: 2,000-10,000 MC paths per A value
  - ML: 500-5,000 MC paths per A value

This seems like a lot! Why not enough?

Standard error of std estimate:
  SE(std) ≈ std / √(2N)

For std ≈ 1.3, N = 5,000:
  SE ≈ 1.3 / √10,000 ≈ 0.013

So measured std ≈ true std ± 0.026 (95% CI)

When Classical and Optimized differ by ~0.05 in std,
this is only ~2 standard errors - barely significant!

To reliably detect 0.05 difference, would need:
  N ≈ (1.96 × 1.3 / 0.05)² / 2 ≈ 1,000,000 paths!

Practically infeasible for repeated optimization.

6. ML-SPECIFIC FAILURE MODES
-----------------------------

Gaussian Process assumptions:
  - Smooth objective function
  - Stationary noise
  - Observations reflect true function values

Reality of MC optimization:
  ✗ Non-smooth (MC noise creates roughness)
  ✗ Non-stationary (variance changes with A)
  ✗ Noisy observations (sampling error)

GP models the NOISE, not the signal!

Example: GP sees std(A=0.28) = 1.276 is lower than
         std(A=0.22) = 1.341 and "learns" that A=0.28 is better.

But this difference is just noise. True function is smooth
and minimized at A=0.22 (Classical).

7. ACQUISITION FUNCTION ISSUES
-------------------------------

Expected Improvement (EI) acquisition:
  - Balances exploration vs exploitation
  - Suggests A values with high uncertainty OR high expected value

Problem: High uncertainty ≈ regions with few observations

In early iterations, GP has high uncertainty everywhere
→ EI suggests extreme A values (A→0 or A→2)
→ These give terrible results, but provide information
→ GP learns to avoid extremes
→ Converges toward reasonable region

But this "reasonable region" is still based on noisy samples!

Classical formula directly gives the right answer: A ≈ 0.2-0.9
(depending on parameters), with NO exploration needed.

8. COMPUTATIONAL COST
---------------------

Grid Search:
  - Evaluations: 11 A values × 2,000 MC = 22,000 total MC paths
  - Time: ~5 minutes (TSLA)

ML (Bayesian Opt):
  - Evaluations: 18 A values × 500 MC = 9,000 total MC paths
  - Time: ~15 minutes (TSLA) - GP fitting overhead!

Classical:
  - Evaluations: 0 (analytical formula)
  - Time: <0.001 seconds

ML is slower than Grid despite fewer MC evaluations (GP overhead)
and MUCH slower than Classical (150,000× slower!)

For what benefit? Worse performance!

   - Encodes optimal tradeoff between hedging error & TC

4. When to use ML optimization
   ✓ No analytical solution exists
   ✓ Problem too complex for theory
   ✓ Empirical validation shows improvement

   ✗ When analytical solution exists (like here!)
   ✗ When sample size insufficient for reliable estimation
   ✗ When theoretical optimum is known

   - Empirical failure of ML confirms formula is truly optimal
   - This is VALUABLE validation of classical theory

WHEN WOULD ML WIN?
================================================================================

Hypothetical scenarios where ML might beat Classical:

1. Non-GBM dynamics
   - Jump processes
   - Stochastic volatility
   - Regime switching
   → No analytical formula exists
   → ML could learn empirically

2. Complex cost structure
   - Non-linear transaction costs
   - Market impact
   - Time-varying costs
   → Leland formula doesn't apply
   → ML could adapt

3. Multi-asset hedging
   - Basket options
   - Correlation trading
   - High-dimensional problems
   → Analytical solutions intractable
   → ML handles high dimensions

4. Market microstructure effects
   - Bid-ask spreads
   - Liquidity constraints
   - Order book dynamics
   → Not captured in GBM
   → ML could learn from data

But for our problem (single asset, GBM, proportional costs):
  Classical formula is optimal, and ML can't beat it.

PRACTICAL IMPLICATIONS
================================================================================

For quants/traders:
  ✓ Trust classical formulas when applicable
  ✓ Use ML for problems without analytical solutions
  ✗ Don't use ML just because it's "modern"
  ✓ Validate empirically on real data (not just backtest)

For ML practitioners:
  ✓ Understand domain/problem before applying ML
  ✓ Check if analytical solution exists first
  ✓ ML is tool, not magic - know when it fails
  ✓ Negative results are publishable and valuable

For researchers:
  ✓ Test ML against theoretical baselines
  ✓ Use real data, not just simulations
  ✓ Report failures honestly (selection bias problem)
  ✓ Understand WHY methods work/fail

For students:
  ✓ Learn classical theory (still relevant!)
  ✓ ML complements theory, doesn't replace it
  ✓ Simple solutions often beat complex ones
  ✓ Empirical validation is essential

Hypothesis H2 was NOT CONFIRMED because:

1. ML optimization (Bayesian + GP) is better than Grid Search
   - More efficient, adaptive, fewer evaluations needed
   - Consistently finds better A on calibration data

2. BUT ML still can't beat Classical Leland formula
   - Overfits to finite Monte Carlo samples
   - Optimizes noisy objective function
   - Doesn't leverage problem structure/theory

3. Real data validation shows Classical is optimal
   - TSLA: Classical wins by $14.28 (14.3%)
   - AAPL: Classical wins by $0.34 (2.5%)
   - Wins in 89% of sensitivity test cases

4. This is a VALUABLE negative result
   - Validates Leland's 1985 theoretical derivation
   - Shows limits of black-box optimization
   - Demonstrates importance of domain knowledge

Key lesson: ML is powerful tool, but doesn't always beat
            domain-specific analytical solutions.

When you have a mathematically rigorous solution (like Leland),
use it! Don't try to "improve" it with ML unless you have
very good reason (and empirical validation).

Recommendation: Use Classical Leland formula:
  A = (k/σ) × √(8/(π×Δt))

Save time, avoid overfitting, get optimal performance.
